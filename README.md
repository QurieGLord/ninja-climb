# Ninja Climb 2.1 · Путь в облака

Вертикальная 2D action-platformer-аркада на **Phaser 4.2.1, TypeScript, Vite и npm**. Ручной прыжок, удержание/скольжение по стенам, wall-jump, направленный воздушный рывок и катана. Приземление **не** запускает следующий прыжок. Игра работает без собственного backend.

## Запуск и проверка

Для запуска в Linux откройте **`Ninja-Climb.desktop`** двойным щелчком. Ярлык настроен для текущей папки проекта. Если файловый менеджер запросит разрешение на запуск, подтвердите его. Универсальный вариант для запуска из терминала в папке проекта:

```sh
./start-game.sh
```

Запускатель сам находит Node.js (включая установленный runtime Codex), при необходимости устанавливает зависимости через npm, запускает локальный Vite-сервер и открывает браузер. Если игра уже работает на **http://127.0.0.1:4173/**, используется существующий сервер и тот же профиль сохранений. Для остановки нового сервера закройте его терминал или нажмите Ctrl+C. `./start-game.sh --no-open` запускает без открытия браузера; `NINJA_PORT=4179 ./start-game.sh` задаёт другой порт, у которого будет отдельный локальный профиль. После переноса проекта в другую папку используйте `start-game.sh` или обновите пути ярлыка.

Нужны Node.js **22.12+** (рекомендуется 24, `.nvmrc`) и npm 10+.

```sh
npm ci
npm run dev
npm run typecheck
npm run test
npm run build
npm run preview
npm run package:yandex
```

`build` создаёт production в `dist/`; `preview` обслуживает именно её по HTTP. `package:yandex` пересобирает production и создаёт проверенный `release/ninja-climb-yandex.zip` и `release/manifest.json`.

```sh
npx playwright install chromium ffmpeg
npm run build
npm run test:e2e
# Или использовать установленный Chrome:
CHROME_PATH=/path/to/chrome npm run test:e2e
```

Воспроизводимый замер production: видимый активный Chrome, 5 секунд прогрева + 60 секунд реальных jump/dash/attack-команд на плотном тестовом маршруте, смена биомов и боссы. Сервер benchmark поднимается автоматически на 4176, тестовые данные не включаются в игру.

```sh
npm run test:perf
PERF_STRICT=1 npm run test:perf  # p95 ≤18 мс, >25 мс менее 1%
# Диагностика программного GPU / CI:
PERF_SOFTWARE=1 npm run test:perf
PERF_HEADLESS=1 npm run test:perf
```

Отчёт `docs/performance/final.json` содержит среднее/медиану/p95/max, долю длинных кадров, фактический GPU, число WebGL-кадров, CPU/JS-время, видимость/фокус, телеметрию боя и скорость симуляции. Headless и SwiftShader обозначаются отдельно. Сравнение — [PERFORMANCE](docs/PERFORMANCE.md). На 60-герцовом эталонном дисплее используется один нативный RAF, `target: 60`, `smoothStep: true`; ограничитель Phaser 4.2.1 не включён из-за накопительного delta, ускоряющего симуляцию. Физика остаётся 1/120 с.

Тесты браузера используют порт 4173. Для технической пересборки атласов из сохранённых оригинальных рисунков:

```sh
npm run assets:prepare
```

Рисование новых кадров выполнялось встроенным imagegen; команда assets:prepare только отделяет/упаковывает существующие нарисованные позы, выравнивает точки опоры и оптимизирует ресурсы. Node/Sharp нужны только при подготовке, в браузере их нет.

## Управление

| Действие | Клавиатура | Мышь / сенсорный экран |
| --- | --- | --- |
| Движение | A/D или ←/→, независимо от раскладки | Экранные стрелки; удерживание точки поля |
| Прыжок / отталкивание от стены | Space, удержание увеличивает высоту | Отдельная кнопка ПРЫЖОК |
| Направление рывка | Стрелки / W S | Удерживаемое направление либо указатель на поле |
| Рывок | Shift | РЫВОК; правый клик в сторону указателя |
| Катана вперёд | J | УДАР / левый клик |
| Пауза | P / Esc | Кнопка вверху |

Направление рывка фиксируется **в момент нажатия**, поэтому быстрый отпуск стрелки не меняет действие. Без явного направления рывок идёт вверх по диагонали в сторону взгляда. Простое удержание экранной стрелки не атакует.

Начало пути содержит интерактивные задания: движение, прыжок, стена, рывок, попадание. Задания реагируют на реальные действия; их прохождение сохраняется. Ниндзя на уступе стоит, бежит и восстанавливает воздушный рывок. На совместимой стене можно кратко удержаться, затем контролируемо скользить и прыгнуть в обратную сторону. Электрические стены опасны.

Катана действует перед персонажем в ограниченном окне замаха, не в круге вокруг тела. Одна атака наносит одному врагу урон один раз. Воздушное попадание возвращает рывок и даёт небольшой импульс вверх. Комбо продолжается до двух секунд между попаданиями; приземление его завершает. Подброса прежней автопружины нет.

Теневой страж патрулирует и телеграфирует ближний удар. Бумажный дух летает и пикирует на зафиксированную цель. У босса шесть жизней: подготовка → мощный удар → уязвимый отдых. При половине здоровья начинается ускоренная вторая фаза; попадание не продлевает отдых бесконечно. Победа открывает выход арены. Первый босс находится примерно на 288 м, следующие — через 360 м.

Зоны: **Облачные врата (0 м)**, **Синяя ночь (360 м)**, **Пепельный предел (720 м)**. Это три разных нарисованных окружения с разными силуэтами; переход плавный. Дальше восхождение продолжается по проверенным сегментам. Движущиеся уступы переносят персонажа; трескающийся уступ даёт короткое время до разрушения.

Очки: `высота × 10 + боевые очки + очки монет`. Обычный враг даёт 3 монеты, бумажный дух 4, босс 30; подбор — 1 монету и 25 очков. Боевой множитель ограничен ×5. В кошелёк награды записываются сразу, повторного начисления на результатах нет. Три разных косметических костюма сохраняют прежние ID и цены: ember бесплатно, jade 80, moon 160.

## Архитектура

- `game/types.ts`, `movement.ts` — сериализуемая модель персонажа и FSM.
- `collision.ts` — swept-столкновения с полными стенами и односторонними уступами.
- `combat.ts`, `enemies.ts` — направленный клинок, hit-ID, комбо, патруль, пикирование и фазовый босс.
- `level.ts` — проверенные маршруты, отражение сегментов, стены/опасности, арены и врата.
- `RunModel.ts` — координация фиксированного шага 1/120 с, камера, события, снимки и миграция; без Phaser.
- `rendering/assets.ts`, `animation.ts`, `WorldView.ts` — внешние изображения, именованные Phaser-анимации, эффекты и визуальные телеграфы.
- `rendering/interpolation.ts`, `EffectPool.ts`, `LivingWorld.ts` — визуальная интерполяция, ограниченные пулы, многослойный мир; не меняют физику и снимки.
- `scenes/` — загрузка, меню и забег; `systems/` — ввод, пауза, звук, прогресс.
- `sdk/` — единственный адаптер платформы; `ui/` — меню/HUD/обучение/результаты/косметика.
- `data/config.ts` — параметры движения, каталог врагов/опор/зон/костюмов; `data/terrain.ts` — подготовленные точки соприкосновения с нарисованными уступами.

Состояния: idle, running, jumping, rising, falling, landing, wall_cling, wall_slide, wall_jump, dashing, attacking, hurt, dead. Jump buffer и coyote time смягчают точность нажатия. Ускорение/торможение и воздушное изменение направления отделены от ограниченного по времени dash. Пауза останавливает модель, анимации, эффекты и Web Audio; потерянное время не догоняется после возврата.

## Графика

**466 оригинальных нарисованных кадров:** 13 действий × 8 кадров × 3 костюма героя, 56 кадров стража и по 49 кадров духа/босса. Новый стиль — крупные угловатые цветовые плоскости, мягкая cel-тень, гладкие контуры и компактные пропорции. Костюмы меняют одежду, капюшон, пластины и аксессуары, а не только оттенок.

Шесть alpha-trim атласов занимают суммарно **18,17 МиБ RGBA**, вместо примерно 108 МиБ у версии 2.0. Полный костюм загружается по выбору, остальные освобождаются. Меню имеет отдельные чёткие idle-кадры, магазин — компактные превью. Быстрые действия фазируются по существующим физическим таймерам; физика не растягивается ради рисунка.

Все облики в лобби используют общий idle-clock без сброса при переключении. Idle выравнивается по неподвижной точке между стопами: дыхание/шарф не сдвигают персонажа по платформе. Пиксельные проверки отдельно контролируют игровой и крупный menu-масштаб.

12 видов поверхностей включают крыши, сломанные крыши, мох, храмовые основания, бамбук и специальные опоры. На биом приходится шесть самостоятельных слоёв: небо, облака, горы, архитектура, растения и края. Они следуют cameraY с разными коэффициентами; туман, ветви, водопад, фонари и тематические частицы двигаются независимо. У эффектов жёсткие лимиты: 64 искры, 8 следов рывка, 8 надписей.

Основные персонажи, катаны, враги, босс, уступы и стены — внешние растровые ресурсы. `Graphics` используется только для небольших частиц/валюты, следа удара, электричества и телеграфов; не для моделей и поз. Рывок оставляет силуэты текущего настоящего кадра. Отдельные циклы показывают прыжок, падение, стену, рывок, удар, реакцию и гибель.

См. [ART_STYLE_GUIDE_V2](docs/ART_STYLE_GUIDE_V2.md), [ART_ASSET_BRIEF](docs/ART_ASSET_BRIEF.md) и [проверку кадров](docs/ART_FRAME_AUDIT.json). Финальные исходники/промпты встроенного imagegen лежат в `docs/art-source/v2/`; они и чужие изображения `Artworks/` не входят в production. Для версии 2.1 инструменту передавались только наши оригинальные генерации.

## Прогресс и совместимость

Ключ кошелька остаётся **`ninja-climb.progress.v1`**, облачный ключ — `ninjaClimb`. Рекорды, баланс, покупки, выбранный облик, звук и ID активного забега сохраняются. Новые снимки имеют **`modelVersion: 2`** и хранят FSM/таймеры, геометрию, врагов, камеру, seed и обучение.

Старый забег переносится на **безопасную опору новой модели на прежней высоте**. Его очки и уже заработанное сохраняются, старые награды не выдаются повторно. Позиция в старой несовместимой геометрии намеренно заменяется безопасной точкой. После миграции обновление продолжает новый снимок.

Важные изменения записываются локально сразу; монета/награда и состояние её потребления — одной записью JSON. Текущий забег дополнительно сохраняется каждые 0,75 с, при уходе в меню, скрытии страницы и pagehide. Облако загружается до меню; записи объединяются и отправляются через `setData(..., true)` не чаще раза в пять секунд с повтором ошибок. Рекорды и открытые облики объединяются, кошелёк и забег берутся из последней записи. Одновременные офлайн-кошельки не суммируются. Повреждённый снимок не ломает загрузку кошелька.

## Яндекс Игры и ZIP

Адаптер SDK, его контракты и очередь облака сохранены. SDK загружается через платформенный **`/sdk.js`**, не включается в ZIP. На localhost используется реальное локальное хранилище; `?yandex` включает запрос SDK для проверки отказа/прокси. Game Ready отправляется после загрузки всех ресурсов и интерактивного меню. GameplayAPI отражает реальный запуск, остановку и паузы.

Видео вызывается только кнопкой «+25 монет за видео» на результатах. Награда выдаётся **только из настоящего onRewarded, один раз**. Ошибка, закрытие без награды и отсутствие SDK ничего не начисляют. Причины паузы (ручная/фокус/скрытие/SDK/реклама) независимы. Тестовые SDK существуют только в тестах.

Документация платформы: [подключение](https://yandex.ru/dev/games/doc/ru/sdk/sdk-about), [готовность и gameplay](https://yandex.ru/dev/games/doc/ru/sdk/sdk-game-events), [сохранения](https://yandex.ru/dev/games/doc/ru/sdk/sdk-player), [реклама](https://yandex.ru/dev/games/doc/ru/sdk/sdk-adv), [требования](https://yandex.ru/dev/games/doc/ru/concepts/requirements).

ZIP содержит `index.html` в корне, favicon и runtime-ресурсы `assets/`. Валидатор проверяет ASCII-имена без пробелов, типы файлов, отсутствие source maps/исходников/референсов/symlink/обхода путей, дубликатов и лишней папки dist/. Лимит распакованного размера — консервативные **100 000 000 байт**. Архив распаковывается и побайтно сравнивается со сборкой. Manifest содержит размеры, файлы и SHA-256. `base: './'` сохраняет работу во вложенном iframe.
