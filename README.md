# Ninja Climb · Путь в облака

Законченный вертикальный срез браузерной аркады: автопрыжки по крышам, воздушные удары с подбросом, комбо, маски-враги, стражи они, три зоны, результат забега и три косметических облика за заработанные монеты. Игра работает целиком в браузере, без собственного сервера. Phaser **4.2.1**, TypeScript, Vite, npm.

## Запуск

Нужны Node.js **22.12+** (рекомендуется **24 LTS**, см. `.nvmrc`) и npm **10+**. Версии зависимостей зафиксированы в `package-lock.json`.

```sh
npm ci
npm run dev
```

Открыть адрес, который покажет Vite. В локальном режиме игра использует настоящие локальные сохранения; SDK и рекламные блоки не имитируются.

```sh
npm run typecheck       # строгая проверка TypeScript
npm run test            # игровые правила, сохранения, SDK, упаковка
npm run build           # typecheck + production в dist/
npm run preview         # запуск именно production-сборки
npm run package:yandex  # build + проверенный ZIP для Яндекс Игр
```

Дополнительная браузерная проверка:

```sh
npx playwright install chromium
npm run build
npm run test:e2e
```

Если Chrome уже установлен, можно использовать его вместо загрузки Chromium:

```sh
CHROME_PATH=/path/to/chrome npm run test:e2e
```

Браузерные тесты запускают production-preview на порту 4173. Скриншоты и трассировки ошибок сохраняются в `test-results/`; они исключены из Git и релизного архива.

## Управление и правила

| Действие | Клавиатура | Мышь / сенсорный экран |
| --- | --- | --- |
| Направление | ← / → или физические A / D, независимо от раскладки | Удерживать сторону поля либо кнопки со стрелками |
| Воздушная атака | Пробел, W или ↑ | Клик / тап по полю либо кнопка удара |
| Пауза | P или Esc | Кнопка вверху справа |

Ниндзя прыгает автоматически. Приземление работает только сверху. Бирюзовые крыши движутся, песочные разрушаются после одного приземления. Враг при контакте отбрасывает вниз; после удара есть короткая неуязвимость. Успешная воздушная атака подбрасывает вверх. Второй враг в паре позволяет продолжить комбо: до следующей победы даётся 2,4 секунды, касание крыши обнуляет цепочку.

За обычного врага начисляются 3 монеты и 100 × множитель очков, за они — 25 монет и 800 × множитель. Они выдерживает три отдельных удара. Множитель ограничен ×5. Подобранная монета даёт 1 монету и 25 очков. Итог: `высота × 10 + боевые очки + очки монет`. Монеты начисляются в кошелёк сразу, повторного начисления на экране результата нет. Они появляются каждые 420 м; зоны меняются на 300 и 600 м, далее восхождение продолжается.

## Структура

```text
src/
  data/config.ts         # физика, платформы, зоны, враги, каталог обликов
  game/                 # независимая симуляция забега и контракт сервисов
  scenes/               # Boot, Menu, Play
  rendering/            # оригинальные текстуры персонажей, платформ, эффекты
  systems/              # ввод, звук, причины паузы, прогресс и экономика
  sdk/                  # интерфейс платформы и единственный адаптер Яндекса
  ui/                   # меню, HUD, результаты, обучение, облики
public/                 # только ресурсы, используемые игрой
scripts/                # проверка и создание архива
tests/                  # unit и браузерные сценарии; не входят в релиз
```

Коллизии и бой реализованы в `RunModel` с фиксированным шагом **1/120 с**, независимо от частоты отрисовки. Односторонние платформы проверяются по пересечению поверхности, поэтому персонаж не проваливается сквозь крышу при большой скорости. Генератор использует сохраняемое состояние PRNG, ограничивает расстояния прыжка и удаляет оставшиеся далеко внизу сущности. Визуальный слой читает модель, но не определяет экономические награды.

Облики используют стабильные идентификаторы каталога (`ember`, `jade`, `moon`); цена и владение не зависят от цвета, имени текстуры или UI. Все облики косметические. Параметры находятся в `src/data/config.ts`.

Векторный фон и процедурная графика созданы для этого проекта. Изображения в исходной папке `Artworks/` оставлены как референсы и **не используются в игре или ZIP**.

## Сохранения

- Версионированный прогресс хранится в `localStorage` под стабильным ключом `ninja-climb.progress.v1` и в `player.getData/setData` под ключом `ninjaClimb`.
- Монеты, покупка/выбор облика, настройка звука и рекорды записываются локально сразу после изменения. Начисление валюты и состояние уже собранных монет/побеждённых врагов записываются одной транзакцией JSON, чтобы обновление не повторяло награду.
- Текущий забег сохраняется каждые 0,75 с, при изменении рекорда/наград, при выходе в меню, скрытии страницы и `pagehide`. После обновления доступна кнопка «Продолжить». Неуспешный забег очищается; новый начинается с нуля, кошелёк и рекорды остаются.
- Облако загружается до появления интерактивного меню. Записи объединяются и отправляются через `setData(..., true)` не чаще одного раза в 5 секунд; при ошибке очередь повторяет запрос. На `unload` сеть не полагаемся: локальная запись синхронна.
- При слиянии берутся максимальные рекорды и объединяются открытые облики; кошелёк и текущий забег берутся целиком из более свежей записи. `max(balance)` не используется, чтобы облако не отменяло покупки. Одновременная офлайн-игра на разных устройствах использует стратегию последней записи для кошелька, без суммирования независимых балансов.
- Повреждённые и невалидные данные проверяются до восстановления. Недоступное локальное хранилище/облако не вызывает падение игры; статус отображается в интерфейсе. Если браузер блокирует оба хранилища, сохранение между сессиями недоступно.

- [Технические требования и ZIP](https://yandex.ru/dev/games/doc/ru/concepts/requirements)

Адаптер динамически загружает **`/sdk.js`**, который предоставляет платформа. Файл SDK не скачивается и не включается в архив. `YaGames.init()` вызывается после загрузки скрипта. На localhost SDK не запрашивается; `?yandex` включает его загрузку для проверки отказа или локального прокси.

`LoadingAPI.ready()` вызывается после загрузки ресурсов, создания текстур и появления интерактивного меню. `GameplayAPI.start/stop` отражает начало/конец забега и реальные паузы. Загрузка ресурсов, скрипта SDK, инициализация и чтение облака имеют обработку ошибок; SDK-запросы ограничены по времени. При сбое SDK доступен локальный игровой режим.

Пауза хранит отдельные причины: ручная, потеря фокуса, скрытая вкладка, событие SDK и реклама. Возврат одного источника не снимает остальные причины. На паузе останавливаются симуляция, эффекты и Web Audio; зажатые команды очищаются. На мобильном старте адаптер запрашивает полноэкранный режим через SDK.

Видео вызывается **только по кнопке «+25 монет за видео» на экране результата**. Награда выдаётся один раз, только из настоящего `onRewarded`; `onClose`, отсутствие SDK или ошибка награду не дают. Пауза остаётся до закрытия рекламы. Запрос без callback завершается ошибкой через 12 секунд; если реклама уже открылась, ожидание её закрытия не ограничивается этим таймером. Тестовые SDK-объекты существуют только в `tests/`, в production их нет.

### Архив

`npm run package:yandex` создаёт:

```text
release/ninja-climb-yandex.zip
release/manifest.json
```

В корне ZIP — **`index.html`**, `favicon.svg` и папка `assets/`. Скрипт проверяет ASCII-имена без пробелов, отсутствие `..`, абсолютных путей, дубликатов и символических ссылок. Разрешены только runtime-файлы; исходники, source maps, референсы, тесты и лишняя папка `dist/` запрещены. Суммарный **распакованный** размер ограничен консервативными **100 000 000 байт**. После создания ZIP распаковывается в память, повторно проверяется и сравнивается побайтно с исходной сборкой. Отдельный manifest содержит список файлов, размеры и SHA-256.

Vite использует `base: './'`, ресурсы грузятся относительно страницы. Игра проверяется в iframe под вложенным URL. Абсолютный `/sdk.js` — предусмотренный документацией адрес платформенного SDK, а не путь к игровым ресурсам.

## Что проверено и что остаётся

Актуальный отчёт с командами и результатами: [QA.md](QA.md).

Перед публикацией нужен черновик в Консоли Яндекс Игр: включить облачные сохранения и монетизацию, проверить настоящий SDK, индикаторы Game Ready/GameplayAPI, рекламу и сохранения на разных устройствах. Локальные тесты callback-контрактов не подтверждают реальный показ рекламы или приёмку платформой. Необходимо отдельно пройти реальные Android/iOS, Safari, Яндекс Браузер и переходы в/из рекламы, включая звук и полноэкранный режим.
