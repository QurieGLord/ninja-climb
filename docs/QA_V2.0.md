# Ninja Climb 2.0 — фактический QA

Дата: **13 октября 2026 года**. Проверялась production-сборка Phaser **4.2.1**, TypeScript/Vite, через HTTP. Исходное состояние: `3ad9aa4`, `baseline/pre-action-rework`. Работа: `rework/action-platformer`.

## Сохранено и заменено

Без изменений сохранены исходники **YandexAdapter/types, PauseManager, AudioSystem, Vite/TypeScript-конфигурации и валидатор/создатель ZIP**. Это подтверждено сравнением с baseline. Меню, результаты, кошелёк, cloud-очередь, цены/ID косметики и рекламная награда сохранены; ProgressStore дополнен миграцией симуляции и прохождением обучения.

Заменены автопрыжок, радиусный бой, статические процедурные фигуры и независимые случайные крыши. Новое ядро разделено на движение, swept-коллизии, катану/комбо, врагов/босса и сегменты. Ввод поддерживает отдельные jump/dash/attack, а направление dash фиксирует при нажатии. Renderer использует реальные Sprite/Phaser-анимации, оригинальные нарисованные ресурсы, параллакс/туман, короткий след оружия и силуэты рывка.

### Модель и ресурсы

Проверены отсутствие автопрыжка, новый прыжок после приземления, отсутствие повторения от удержания, разная высота от удержания, буфер и coyote time, ускорение/торможение/разворот в воздухе, односторонние опоры, быстрые падения, перенос на движущемся уступе и отложенное разрушение.

Проверены ограниченное cling, ограниченная скорость slide, wall-jump с уходом от стены, восстановление воздушного контроля, электрические поверхности, направленный dash и его длительность/окончание/однократность, сохранение направления после быстрого отпускания клавиши, столкновение dash с тонкой стеной и потолком.

Проверены окно катаны, промах сзади/выше, один урон за замах, однократное начисление, небольшой импульс и восстановление dash, продолжение/истечение комбо, телеграф/удар/уязвимость босса, ускоренная фаза II, отсутствие бесконечного продления уязвимости попаданиями, открытие ворот и награда за победу.

Проверены зеркальные маршруты аналитически и достижимость первой арены контроллером с настоящими jump/dash-командами на физической геометрии. В тесте достижимости враги исключены, чтобы он проверял геометрию; боевые правила и полный бой с боссом проверяются отдельно. Проверены pause, детерминированное продолжение снимка, одинаковое движение при расписаниях 30/120 Гц, миграция старого checkpoint, отказ невалидного нового checkpoint и анимационная фаза смерти до результатов.

Сохранены проверки кошелька, покупки/выбора облика, облачного слияния без отмены покупок, повреждённых данных, ошибок/повторов облака, причин паузы, SDK-рекламы, поздних/повторных callback и упаковки.

Проверены реальные PNG: девять страниц не больше 2048 пикселей, alpha, непустые уникальные кадры каждого действия, отдельные три окружения. Всего 240 нарисованных кадров. Модели персонажей и основные существа не создаются через Graphics; техническая подготовка не генерирует позы.

### Production-браузер

1. Меню/обучение, стояние без автопрыжка, клавиатурное движение, ручной прыжок, dash, пауза, J после возврата, падение, смерть, результаты и повтор. Обычный сценарий без pageerror/console.error.
2. Настоящее направленное попадание → восстановление dash → направленный рывок вверх → второе попадание и воздушное комбо ×2, ровно две награды.
3. Удар мышью, запись монет, покупка нового нарисованного костюма, выбор и активный checkpoint после обновления.
4. Настоящие эмулированные touch-события Chrome: направление + атака одновременно, touchCancel без залипания, отдельный прыжок, портрет 390×844 и поворот 844×390 без скролла.
5. Бой с **шестижизненным боссом**: блок в защищённой фазе, прыжки по телеграфу, атаки в уязвимые окна, фаза II, победа и ровно 30 монет. Персонаж остаётся жив.
6. Реальный AudioContext: running/suspended при blur/focus, сохранение ручной паузы, resume и mute.
7. Ошибка настоящего запроса `/sdk.js` → локальный режим с сохранением.
8. Ошибка загрузки реального атласа героя → понятный retry, без начала пустой игры.
9–10. Ошибки главного JavaScript/CSS → независимый retry до загрузки приложения.
11. Полная сборка/анимационные ресурсы во вложенном iframe `/embedded/index.html`.
12. Контракт SDK в тестовом браузере: Game Ready после меню, ранняя SDK-пауза, cloud errors, рекламная ошибка без награды, настоящий для теста callback onRewarded ровно один раз, закрытие и восстановление.

Подмена SDK существует только в тестовом браузере. В production нет фиктивного SDK, успешной рекламы, тестового экрана или управляющего debug API. В намеренно оборванных сетевых сценариях browser resource errors ожидаемы; нормальный игровой сценарий чист.
