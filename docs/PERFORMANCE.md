# Ninja Climb 2.1 — производительность

13 октября 2026. Один и тот же production smoke-test: видимый/активный Chrome 155 Linux, **NVIDIA GeForce GTX 1050 Ti**, ANGLE/OpenGL ES 3.2, viewport 1440×900, 60-Гц RAF. 5 секунд прогрева + **60 секунд замера**. Во время итогового прогона другие browser-тесты не запускались.

80 статических/движущихся опор и 40 врагов в fixture; первые 10 секунд — настоящий бой катаной, переход босса I→II, затем 50 секунд подъёма с прыжками, направленными dash, воздушными ударами/комбо, эффектами и сменой трёх биомов. Изменён только тестовый checkpoint (invincibility), production debug API/тестовой сцены нет. Финал: 5 побед, combo ×3, фаза II подтверждена, высота 2121 м, console/page errors 0.

Цели p95 ≤18 мс и >25 мс <1% выполнены. В итоговом прогоне два кадра превысили 25 мс (максимум 33,4 мс). **В предыдущем прогоне был редкий кадр 133,3 мс**; он сохранён в [prior-final-hitch.json](performance/prior-final-hitch.json), хотя JS Long Tasks не было. Этот результат не удалён и не скрыт за средним FPS. Результат не означает полное отсутствие джиттера. Более богатая графика требует больше растеризации; снижение draw calls не доказывает меньшую стоимость каждого пикселя.

RAF-интервалы — прокси композиции, дополнительно считаются реально поданные WebGL-кадры. Физический вывод монитора/латентность ввода прибором не измерялись. CPU TaskDuration/ScriptDuration — CDP; heap — моментальный performance.memory, не точная GPU-память. Атласы: шесть основных страниц 18,17 МиБ RGBA для ВСЕХ костюмов, плюс 2,19 МиБ menu-idle на выбранный. Полный костюм загружается по выбору, остальные удаляются; окружение/опоры занимают дополнительную память.

## Сравнение и диагностика

Baseline-коммит ac3b097 собран отдельно в /tmp и обслуживался на 4177; рабочая ветка не переключалась. JSON: [baseline](performance/baseline.json), [final](performance/final.json), [исходный ZIP](performance/baseline-release.json). Нативный RAF, target 60, smoothStep true. Phaser 4.2.1 fps.limit=60 оказался непригоден: передаёт остаток аккумулятора в delta и в диагностике ускорил минуту симуляции примерно до двух. Лимитер удалён, физика по-прежнему 120 Гц; итоговые часы нормальны. На мониторе с большей частотой нативный RAF может рендерить чаще 60 Гц — тест не является универсальным жёстким ограничителем.

Отдельные ранние SwiftShader-прогоны: [baseline software](performance/baseline-software.json) ~44 FPS, [до сокращения overdraw](performance/before-overdraw-fix.json) ~20 FPS, [после](performance/after-overdraw-fix-software.json) ~22 FPS. Тогда использовался более ранний controller, поэтому это диагностика цены software-GPU, а не итоговая сопоставимая таблица. GPU-растеризация ограничивала темп при малом CPU/JS времени. Слои не удалялись ради цифр; их пустые края обрезаны, эффекты переведены в пулы, невидимые sprites не рисуются. [Диагностика ограничителя времени](performance/limiter-clock-diagnostic.json) сохранена и не используется как итог.

## Воспроизведение

`npm run test:perf` собирает production и поднимает отдельный preview на 4176. `PERF_STRICT=1` делает превышение p95/доли длинных кадров ошибкой. `PERF_SOFTWARE=1` принудительно включает SwiftShader; `PERF_HEADLESS=1` — headless. `CHROME_PATH` задаёт Chrome; `PERF_URL` использует уже запущенный production для baseline. Не запускать параллельно другие браузерные тесты/профилировщики. Все измерения/fixture находятся в scripts, вне release.

Реальные Android/iOS, Safari и слабый мобильный GPU **не проверены**. Нельзя переносить desktop 60 FPS на телефоны без измерения. Нужны длительная игра, нагрев, возврат из фона и черновик Яндекс Игр с настоящей рекламой/SDK.
